# NSR 분석 파이프라인

근무 녹음 → 학습 자료로 가는 전체 공정. 코드는 `apps/mobile/src/services/pipeline.ts`
(3a·3v·3b·4)와 `llm.ts`(5·5b), 상태는 DB `pipeline_jobs` 에 있다.

## 단계 (순차 의존 — 앞이 실패하면 뒤로 넘기지 말고 중단)

| 단계 | 처리 | 입력 | 출력 | 권한 |
|---|---|---|---|---|
| 1 | 전사 (Whisper 계열: 콜랩 WhisperX/PC/Gemini) | 원본 오디오 | 전사 세그먼트 | — |
| 2 | 마스킹 (`redactForNetwork`, 로컬) | 전사본 | 마스킹 전사본 | — |
| 3a | 1차 분석 — 추출 (재현율 담당) | 마스킹 전사본 전체 | 교정목록·판독불가·교육포인트·근무요약·근무환경분석·용어사전 | — |
| 3v | 검증 패스 (하이브리드 경로 전용) | 3a 교정목록 + 마스킹 전사본 | 검증결과(유지/강등/기각) | — |
| 3b | 2차 심화 — 조사 (웹 검색 켬) | 3a(+3v) JSON + 마스킹 전사본 | 재해석·지식보강·교육포인트_보강 | — |
| 4 | 보고서·카드 | 3a(+3v)+3b JSON **만** (전사본 금지) | 보고서 3섹션·카드·확인목록 | 쓰기 |
| 5 | 일상 대화 | 카드·보고서·확인목록·세션 대화 전체 (상시, 자르지 않음) | 대화 | **읽기 전용** |
| 5b | 임상 판단 승격 (수동 버튼만) | 5 + 판단근거·(3v 검증결과)·지식보강 | 대화 + 수정 도구 5종 | 읽기+쓰기 |

모델 배정과 근거는 `provider-routing` 스킬, JSON 필드와 검증 규칙은
`pipeline-schema` 스킬이 정본이다.

## 어길 수 없는 규칙

- **마스킹 로직은 건드리지 않는다.** 기기 밖으로 나가는 모든 텍스트는
  `redactForNetwork` 를 거친다. 원본 오디오는 전사(1단계) 서버로만 간다.
- **판독불가의 웹 재해석은 교정목록에 절대 병합하지 않는다.** 별도 배열 +
  `확인필요: true` → 확인 목록(confirmations 테이블)으로만 나간다.
- **5단계는 구조적 읽기 전용** — 수정 도구를 요청에 싣지 않는 것으로 보장한다.
  수정 요청에는 임상 판단 모드 전환을 안내한다.
- **5b 는 수동 버튼으로만** 켜진다. 자동 라우팅을 만들지 않는다. 모든 수정은
  `reason` 필수 + `change_history` 에 이전 판째 보관.
- 검색은 3b(항상)와 5b(토글)에서만. 3a·3v·4·5는 검색 없음.
- 배치 결과는 순서 미보장 — `custom_id` 로만 매칭한다.
- 한 제공사 장애·미연결 시 **다른 모델로 자동 대체하지 않는다.** 이유를
  화면에 표시하고 다른 경로 선택을 안내한다.
- 프롬프트 캐싱·롤링 요약·자동 모델 라우팅은 구현하지 않는다(사용자 결정).

## 경로

- **Claude 단독** (구현됨): 3a=claude-opus-5(high) / 3b=claude-fable-5+검색 /
  4·5=gemini-3.7-flash / 5b=claude-opus-5(high). 3v 없음.
- **GPT+Gemini 하이브리드** (사양 확정, 구현 여부는 코드 확인): 3a=gpt-5.6-sol /
  3v=gemini-3.7-flash(기계 검증 선행) / 3b=gemini-3.1-pro+검색 /
  4·5=gemini-3.7-flash / 5b=gemini-3.1-pro. 두 경로는 **같은 출력 스키마**를
  산출해야 뒷단(4·5·5b·화면)이 공유된다.

## 재개(복구) 모델

폰 앱은 언제든 죽는다. 단계·배치 id 를 `pipeline_jobs` 에 저장하고,
`checkDeepAnalysis()` 는 "지금 가능한 다음 한 걸음"만 민다. 화면이 열려
있으면 30초 주기, 아니면 '진행 확인' 버튼. 새 단계를 추가하면 반드시
중간 상태(제출 직전 죽음 포함)를 재개할 수 있게 설계한다.

# 파이프라인 JSON 스키마

필드 정의의 정본은 같은 폴더의 [schema.json](schema.json)이다. 코드의
프롬프트·파서가 이 파일과 어긋나면 **코드가 틀린 것**이다.

## 최상위 제약

- **세 경로(Claude 단독 / GPT 단독 / 하이브리드)는 동일한 스키마를 산출해야
  한다.** 뒷단(4단계·화면·5b 도구)이 스키마를 공유하기 때문이다. 하이브리드
  전용 산출물(3v `검증결과`)은 경로 내부용이며, 4단계 입력에는 실리되 다른
  경로가 흉내낼 필요는 없다.
- 필드명은 한국어 그대로 쓴다 (`교정목록`, `판독불가`, …). 바꾸려면 세 경로와
  schema.json, 프롬프트, 파서를 한 번에 바꾼다.

## 검증 규칙 (코드로 강제)

1. **`원문인용`은 전사본에서 글자 그대로 복사**한 것이어야 한다. 요약·정리 금지.
   3v 앞의 **기계 검증**이 전사본 문자열 포함 여부를 대조하고, 불일치면 LLM 에
   묻지 않고 `판독불가`로 강등 + 사유 기록한다.
2. **`확인필요: true` 항목은 카드로 만들지 않는다.** 확인 목록(confirmations)
   으로만 나간다. 웹 검색 유래 추정은 예외 없이 `확인필요: true`.
3. **`add_card` 는 유효한 `source_id` 를 요구한다.** 존재하지 않는 id 면 코드가
   거부한다 — 근거 없는 카드 생성을 모델 재량에 맡기지 않는다.
4. 출처(`출처` URL 배열) 없는 조사 결과는 버린다.
5. 확신 없으면 `교정목록`이 아니라 `판독불가`다. 애매하면 버리지 말고
   `확신도: "하"`로 남긴다 — 걸러내는 건 다음 단계다.

## 단계별 출력 (요약 — 전체는 schema.json)

- **3a**: `교정목록[] · 판독불가[] · 교육포인트[] · 근무요약 · 근무환경분석 · 용어사전[]`
- **3v**: `검증결과[] { 교정_id, 판정: 유지|강등|기각, 사유, 인용일치 }`
- **3b**: `재해석[] · 지식보강[] · 교육포인트_보강[]` — 재해석은 교정목록에 병합 금지
- **4**: `보고서 { 사실정리, 해석과교육, 근무환경분석 } · 카드[] { 앞면, 뒷면, 출처ID } · 확인목록[]`
  — 카드가 될 수 있는 것은 (하이브리드에서) 3v `유지` 판정 교정뿐이다.

# NSR 전사본 검토

이 스킬은 **실제 전사본을 교정하면서 채워 가는 기록**이다. 사용자가 휘스퍼 전사본을 보내면
Claude 가 교정하고, 그때 확정된 판단만 `references/` 에 남긴다. 다음 세션과 API 스킬은
그 기록을 기준으로 같은 판단을 한다. 여기 없는 기준을 즉석에서 지어내 확정하지 않는다.

## 지금 상태

- 채워진 교정 세션: **0회.** `references/decisions.md`(확정 기준)와 `references/log.md`(세션 기록)는 비어 있다.
- 비어 있는 동안의 태도: 문맥으로 후보를 세우되, 확신이 서지 않으면 **묻는 쪽**으로 기운다.

## 사용자가 정한 틀 (바뀌지 않는 부분)

1. 오류를 세 갈래로 가른다 — **A 반복**(같은 말이 되풀이됨), **B 임상 어휘 부재**(모델이 모르는 용어를 다른 말로 적음), **C 순수 한글 오독**(평범한 말을 잘못 적음). 어느 갈래인지 먼저 정한다.
2. **문맥으로 더블체크**한다. 문장 하나가 아니라 앞뒤 대화를 보고, 그 자리에 맞는 어휘인지 본다.
3. 대화 문맥에서 **어떤 단어가 적절한지 추론**해 후보를 세운다.
4. **판독 불가**는 추측해서 확정하지 않고, 파일명·시각·문장을 붙여 사용자에게 묻는다.
5. 녹음본 여러 개를 넣어 **서로 교정**하며 확정을 쌓는다. 같은 오인식은 두 번 묻지 않는다.
6. 충분히 쌓이면 이 스킬 파일을 점검해 각 AI(Claude Code · Claude API)에 보낼 판을 만든다.

## 저장소 규칙에서 오는 대전제

- `rawText`(원문)는 보존한다. 교정은 별도 기록이다.
- 화자가 실제로 한 말(은어 "폴리")은 고치지 않는다. 음성인식이 틀린 것만 고친다.
- 환자 실명·등록번호·병실은 산출물과 질문에 옮기지 않는다. 환자A·환자B 로 쓴다.
- 자세한 것: `CLAUDE.md` 절대 규칙, `nsr-privacy` 스킬.

## 절차

1. **결정적 1차 검토를 돌린다.** 사람이 읽기 전에 규칙이 잡을 수 있는 것을 걷어낸다.
   ```bash
   node tools/review-transcript.mjs data/transcripts/<파일>
   ```
   `data/reviews/<파일>.review.md` 에 자동 적용(사전에 이미 있는 오인식·약어 읽기·이전 확정) ·
   확인 필요 · 질문 후보가 나온다. 도구는 **후보만** 모은다. 갈래 판정은 하지 않는다.
2. **후보마다 갈래를 정한다.** 기준은 `references/decisions.md`. 거기 없는 경우는 문맥으로
   후보를 세우고 확신 등급을 낮게 매긴다.
3. **문맥 더블체크.** 앞뒤 2~3문장, 지금 어느 환자·어떤 처치 얘기인지, 제안한 말을 넣어 문장이
   되는지, 옆의 숫자·단위와 맞는지 본다.
4. **판정표를 쓴다** (아래 형식). 확신 높음/중간/낮음을 반드시 적는다.
5. **낮음은 질문으로 넘긴다** (아래 형식). 한 번에 15개 이내, 투약 > 처치 > 검사 > 업무 순.
6. **답을 받으면 기록한다** (아래 "확정 후").

## 판정표 형식

| # | 파일 | 시각 | 원문 | 갈래 | 제안 | 근거 (문맥) | 확신 |
| --- | --- | --- | --- | --- | --- | --- | --- |

표 뒤에 한 줄: 자동 적용 n건 / 확인 요청 n건 / 질문 n건.

## 질문 형식

파일명과 시각이 없는 질문은 내지 않는다 — 사용자가 녹음의 그 지점을 찾아 들어야 한다.

```
[질문 1] 파일: 2026-08-24_D_01.json · 시각: 00:12:34
문장: "… [?원문 표기] …"   (환자 정보는 가린 채로)
후보: ① … ② … ③ 다른 말
왜 못 정하나: …
```

## 확정 후

사용자 답을 받으면 그 자리에서:

1. `references/log.md` 에 세션 기록 한 줄 — 파일·시각·원문 표기·확정 표기·갈래·근거. 문장 원문은 가린 형태로만.
2. 판별 **기준**으로 일반화할 수 있는 것(같은 종류가 두 번 이상 나왔거나, 사용자가 "앞으로 이렇게" 라고 한 것)은 `references/decisions.md` 로 올린다.
3. `data/corrections/confirmed.jsonl` 에 규칙 한 줄 (형식은 `data/README.md`). 다음 검토부터 도구가 먼저 적용한다.
4. B 갈래가 두 번 이상 확정되면 `packages/core/src/lexicon/misheard.ts` 에 올리고 회귀 테스트를 함께 넣는다 (`test-driven-development`). C 갈래는 사전에 넣지 않는다. A 갈래는 규칙으로 만들지 않는다.
5. 내 판정을 사용자가 뒤집은 경우는 `references/decisions.md` 의 "뒤집힌 판정" 에 적는다. 다음 세션이 같은 실수를 안 하게.

## API 스킬로 쓰일 때

`tools/upload-skill.mjs` 로 이 폴더가 그대로 Claude API 에 올라간다. 그때 모델은 저장소도 도구도
없이 이 문서와 `references/` 만 읽는다. 절차 1은 건너뛰고, 출력은 판정표 + 질문만 낸다.
입력의 `[이름]` 같은 가림 표시는 그대로 둔다.

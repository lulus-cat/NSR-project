# NSR | 신규간호사 근무 기록·학습 앱 | 간호 레코딩 플랫폼

> **NSR (Normal Sinus Rhythm)**  
> _noun_ | _의학 용어_
> 
> 심장의 동방결절에서 시작된 전기 신호가 정상적인 경로를 따라 규칙적으로 뛰는 상태 (정상 심박동).  
> _"Restoring the chaos of a shift back to NSR."_  
> _(혼란스러운 근무를 다시 규칙적이고 안정적인 정상 심박동으로 되돌리다.)_

## 소개

**NSR(신규간호사 근무 기록·학습 앱)** 은 인계 시간마다 쏟아지는 낯선 용어들과 그로 인한 혼란(Arrhythmia)을 방지하고, 신규 간호사의 일상을 다시 규칙적인 정상 심박동(NSR)으로 되돌리기 위해 설계된 온보딩 보조 프로젝트입니다.

신규 간호사에게 임상 현장은 낯선 언어의 홍수와 같습니다. 처음 듣는 인계 내용은 귓가를 스치고, 근무가 끝나면 무엇을 들었는지조차 흐릿해집니다. 다음 날 같은 상황에서 또다시 막히고, 그 사이 "내가 예민한 건가", "내가 부족한 건가" 하는 자기 의심만이 남게 됩니다.

NSR은 그 **흐릿해지는 기억의 조각들을 단단하게 붙잡아두는** 역할을 합니다. 근무 환경을 기록하고, 스쳐간 말들을 학습 자료로 변환하여 신규 간호사의 온전한 적응을 돕습니다.

해당 페이지는 NSR 코어 모듈 및 기능의 카탈로그입니다.

# 핵심 모듈 목록

**NSR 프로젝트의 기능은 신규 간호사의 생존과 학습이라는 목적 아래 세분화됩니다.**

## NSR - 스텔스 레코딩 (v1.0.0)
근무 중 발생하는 모든 음성을 소리, 진동, 알림 없이 조용히 기록합니다. 
> ⚠ **한계 사항:** iOS 14+ 및 Android 12+ 환경에서는 OS 정책상 마이크 사용 표시를 완전히 숨길 수 없습니다.
> ⚠ **법적 경고:** 본인 음성이 포함되지 않은 '타인 간의 대화' 8시간 통째 녹음은 통신비밀보호법 위반(1년 이상 징역)입니다. 이를 방지하기 위해 **본인 음성이 없는 구간은 자동으로 파기됩니다.**
> ⚠ **사내 규정:** 법적 문제와 별개로, 병원 취업규칙 위반으로 징계 사유가 될 수 있으니 주의가 필요합니다.

## NSR - 임상 트랜스크립터 (v1.0.0)
일반적인 음성 인식이 아닌, 의학 및 간호 용어에 최적화된 전사(Transcription) 및 교정 기능을 제공합니다.
> ⚠ 화자의 실제 발언을 훼손하지 않기 위해 **말한 내용과 표기를 엄격히 구분합니다.**
> "카데타 → 카테터"는 단순 음성인식 오류이므로 교정하지만, "폴리 → 유치도뇨관"은 화자가 실제로 한 말을 바꾸는 것이므로 원문을 유지하고 주석과 학습 카드로 대체합니다.

## NSR - 스터디 덱 (v1.0.0)
더 이상 들은 것을 잊어버릴까 두려워하지 마세요. 전사된 기록을 바탕으로 암기 카드, 맞춤형 학습 자료, 그리고 근무 보고서를 자동 생성합니다. 공식 자료(병원간호사회 지침 등)와의 출처 연결을 지원하여 학습의 신뢰도를 높입니다.

## NSR - 3계층 은어 사전 (v1.0.0)
임상 현장 특유의 은어를 해석합니다. 487개의 기본 항목과 2,259개의 표기형을 제공하며, **내장 사전 < 병동 사전 < 내 사전** 의 3계층 구조로 작동하여 구체적인 사전이 항상 우선시됩니다.
> ⚠ 병동 사전은 선배가 만들어둔 파일을 공유받아 쉽게 적용할 수 있습니다. 단, 오타 하나로 투약 숫자가 바뀔 수 있는 위험을 방지하고자 **자동 켜짐 기능은 비활성화되어 있습니다.**

## NSR - 국소 지진계 (태움 감지 지표) (v1.0.0)
근무 중 발생한 폭언이나 괴롭힘 발언을 탐지하고 기록하여 수치화합니다.
> ⚠ **주의:** 이 지표는 절대적인 판정 기준이 아닙니다. 텍스트에는 어조나 표정, 맥락이 담기지 않으므로, 화면에서는 점수를 작게 표기하고 **실제로 들은 인용문**을 가장 크게 보여줍니다.

## NSR - 오토 듀티 (v1.0.0)
듀티표와 근무 시간을 연동하여 필요한 구간에만 자동으로 녹음을 활성화합니다. (iOS 환경에서는 일부 제약이 존재합니다.)

# 시스템 철학 및 아키텍처

**설계에서 결코 양보하지 않은 원칙들입니다.**

* **절대적 원본 보존:** `rawText`(ASR 원문)와 원본 오디오는 어떠한 경우에도 덮어씌워지지 않고 보존됩니다. 편집된 파일만 남은 기록은 증거로서의 가치가 없기 때문입니다. 모든 교정은 개별 수락/거절이 가능한 별도 레코드로 남습니다.
* **온디바이스 최우선:** 전사와 분석 등 핵심 로직(Whisper 등)은 접속형 서비스가 아닌 기기 내부에서 처리됩니다. 비행기 모드에서도 작동하며, 외부 전송은 철저히 '옵트인(선택 동의)' 방식입니다.
* **자동 폐기 사이클:** 보관하지 않는 것도 중요한 기능입니다. 오래된 녹음을 방치하는 것은 가장 큰 개인정보 위협이므로, 보관 기간이 지난 녹음은 자동으로 영구 삭제됩니다.
* **플랫폼 독립적 코어:** 핵심 로직(`packages/core`)은 플랫폼 API에 전혀 의존하지 않으며, 314개의 단위 테스트를 통해 철저히 검증됩니다. 앱 코드는 오직 화면 렌더링과 저장만을 담당합니다.

# 미구현 모듈 및 개발 노트

아직 완성되지 않았거나 주의가 필요한 영역입니다.

* **화자 분리 온디바이스 구현:** 인터페이스와 데이터 모델은 준비되었으나, 실제 임베딩·클러스터링 모델이 아직 연결되지 않았습니다. (현재는 수동 라벨링 필요)
* **본인 음성 판정기 부재:** 본인 음성 외 구간 폐기 로직은 존재하나, 자동 식별기가 없습니다. 해당 모듈이 완성되기 전까지는 사용자가 항상 기기를 몸에 지니는 방식으로만 위험을 관리해야 합니다.
* **실기기 검증 (whisper.cpp):** 어댑터는 작성되었으나 실제 모바일 기기에서의 동작 테스트가 아직 완료되지 않았습니다.
* **약어 표의 교차 검증:** 제공되는 328개 약어의 한글 뜻은 일반적 용법 기준입니다. 병원 및 진료과마다 차이가 있으므로 실제 투약 판단 시에는 **반드시 소속 기관의 기준과 처방 원문을 교차 검증**해야 합니다.

### 개발 및 실행 가이드

**코어 (테스트 및 타입체크)**
```bash
npm install
npm test          # vitest 314개
npm run typecheck
```

**모바일 앱 (Expo)**
> ⚠ Expo Go에서는 온디바이스 전사(네이티브 모듈)가 동작하지 않아 별도의 개발 빌드가 필요합니다.

```bash
cd apps/mobile
npm install
npx expo install --fix        # SDK 버전에 맞춰 의존성 정렬
npx expo run:ios              # 또는 run:android
```
온디바이스 전사(whisper.cpp) 바인딩 추가 시:
```bash
npx expo install whisper.rn
npx expo prebuild
```

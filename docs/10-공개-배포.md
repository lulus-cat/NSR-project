# 공개 배포 — 무엇을 바꾸고 무엇을 안 바꾸나

혼자 쓰던 앱을 남에게 나눠 줄 때 달라지는 것을 적는다. 코드보다 **누가 무엇을
갖게 되는가**가 먼저다.

앞선 문서를 전제한다 — `01-legal-and-privacy.md`(왜 못 내보내는가),
`08-app-ai-boundary.md`(폰·VPS·대화 AI 의 경계).

---

## 1. 두 갈래

| | **B — 서버 없이** (기본) | **A — 자기 서버** (고급) |
| --- | --- | --- |
| 누가 쓰나 | 거의 모두 | VPS 를 돌릴 줄 아는 사람 |
| 전사본이 어디까지 가나 | 폰 → (사람이 복사) → 자기 클로드·GPT | 폰 → 자기 VPS → 자기 클로드·GPT |
| 서버 공격면 | **없음** | 자기 서버 하나 |
| 자동으로 되는 것 | 없음 (사람이 붙여넣는다) | 보고서·카드·교정·근무 체온이 저절로 폰에 |

**C(한 대를 여러 사람이)는 하지 않는다.** 그 순간 남의 병동 대화가 담긴 서버를
개인이 운영하게 되고, 개인정보보호법상 처리자가 된다 — 유출 시 신고 의무와
과징금이 따라온다. 마스킹한 사본이라도 재식별 가능성이 있으면 개인정보다.
서버 코드에는 '사용자' 개념이 아예 없다. 만들지 않는 편이 안전하다.

## 2. 배포용 열쇠 (한 번만)

지금까지는 안드로이드가 만들어 주는 **디버그 열쇠**로 서명했다. 그 열쇠는
모두의 컴퓨터에 똑같이 들어 있다. 남에게 나눠 주기 시작하면 두 가지가 문제다.

- 누구나 "NSR" 인 척하는 APK 를 만들 수 있고, 폰은 그걸 같은 앱의 새 판으로 받는다
- 나중에 제대로 된 열쇠로 바꾸면 받은 사람은 **전부 지우고 다시 깔아야** 한다.
  그때 앱 안의 녹음과 전사본이 같이 사라진다

그래서 **공개 전에** 바꾼다. 컴퓨터에서 한 번만 하면 된다.

```bash
keytool -genkeypair -v \
  -keystore nsr-release.keystore \
  -alias nsr -keyalg RSA -keysize 4096 -validity 10000 \
  -storetype PKCS12
```

비밀번호를 물으면 정해서 넣고 **비밀번호 관리자에 저장한다.** 이름·조직을 묻는
것은 아무렇게나 적어도 되지만, 나라(country code)는 `KR` 로 한다.

그다음 이 파일을 GitHub 비밀로 올린다.

```bash
base64 -w0 nsr-release.keystore > keystore.txt   # 맥이면 base64 -i ... -o ...
```

GitHub → 저장소 → Settings → Secrets and variables → Actions → New repository secret

| 이름 | 값 |
| --- | --- |
| `NSR_KEYSTORE_BASE64` | `keystore.txt` 의 내용 통째로 |
| `NSR_KEYSTORE_PASSWORD` | 위에서 정한 비밀번호 |
| `NSR_KEY_ALIAS` | `nsr` |
| `NSR_KEY_PASSWORD` | 비밀번호 (따로 안 정했으면 위와 같게) |

**`nsr-release.keystore` 파일 자체를 잃어버리면 끝이다.** 그 앱을 업데이트할
방법이 영영 없어진다. 저장소에 올리지 말고, 백업은 따로 둔다.

넣고 나면 다음 빌드부터 저절로 그 열쇠로 서명된다. CI 로그에
`서명: 배포용 열쇠로 바꿨습니다.` 가 찍히면 된 것이다. 비밀이 없으면
`서명: 배포용 열쇠가 없어 디버그 서명으로 만듭니다` 가 찍힌다.

## 3. B — 서버 없이 쓰는 길

앱은 혼자서 녹음·티로 가져오기·사전 교정·카드까지 한다. 서버가 하던 일은
"AI 가 알아서 읽고 써 주는 것" 하나뿐이다. 그것을 사람 손으로 바꾼다.

1. 근무 기록 화면에서 **전사본 내보내기**
2. 클로드나 GPT 에 붙여넣고 분석을 시킨다 (지침은 `ai-instruction.md`)
3. AI 가 준 보고서를 **근무 보고서 붙여넣기** 로 앱에 넣는다
4. 카드는 보고서에서 저절로 만들어진다

나가는 것은 **사람이 직접 복사한 것뿐이고**, 그것도 마스킹을 통과한 사본이다.
붙여넣는 순간 그 글은 그 사람의 클로드·GPT 계정에 남는다 — 그 사실을 앱이
내보내기 직전에 말한다.

## 4. A — 자기 서버를 세우는 길

`server/README.md` 를 따른다. 공개 배포에서 달라지는 것 둘.

**첫째, 서버를 켜고 바로 폰을 이을 것.** 이어진 기기가 하나도 없는 동안에는
첫 요청이 그냥 이어진다(처음 한 번만 열리는 문). 문은 30분 뒤 닫히지만,
도메인은 인증서 기록으로 공개되므로 그 30분 동안은 도메인을 아는 누구나 먼저
붙을 수 있다. **서버를 켜 두고 며칠 뒤에 폰을 잇지 않는다.**

**둘째, `NSR_PUBLIC_HOST` 에 도메인을 적을 것.** `*` 는 이제 받지 않는다.
끄면 DNS 리바인딩으로 남의 브라우저가 그 서버를 대신 부를 수 있다.

### MCP 커넥터 — 누가 누구인지

**식별할 '유저들' 이 없다.** 서버 하나에 사람 하나다. 서버가 묻는 것은
"너 누구냐" 가 아니라 **"이 서버의 폰을 쥔 사람이냐"** 다.

```
클로드에 https://nsr.내도메인/mcp 를 넣는다
        ↓
커넥터가 스스로 등록한다 (DCR)      ← 등록만으로는 아무것도 못 읽는다
        ↓
서버가 여섯 자리 번호를 띄운다
        ↓
NSR 앱 → 설정 → 분석 서버 → 승인 번호   ← 여기서 막힌다
        ↓
그 클로드 계정에 열쇠(토큰)가 나온다     30일, 자동 갱신
```

남이 도메인을 알아내 커넥터를 등록해도 네 번째 줄에서 멈춘다. 승인할 폰이
없으면 열쇠가 나오지 않는다.

- **클로드** — 설정 → 커넥터 → 사용자 지정 커넥터 추가 → 위 주소
- **챗지피티** — 설정 → 커넥터 → 새 커넥터 → 위 주소.
  개발자 모드(설정 → 보안)를 켜야 쓰기까지 된다. 안 켜면 `search`·`fetch` 로
  **읽기만** 된다

토큰을 끊으려면 서버 DB 의 `oauth_tokens` 를 비운다. 폰을 잃어버렸으면 앱의
**다른 기기 끊기** 로 나머지를 전부 끊는다.

## 5. 앱이 지키는 것 (두 갈래 공통)

| 무엇 | 어떻게 |
| --- | --- |
| 앱 잠금 | 처음 설정을 마치면 **켜진 채로 시작**한다. 설정에서 끌 수 있다 |
| 보관기한 | 글자로 바꾼 녹음의 소리는 30일 뒤 지워진다. 안 보낸 녹음은 그대로 둔다 |
| 열쇠 | 티로 열쇠는 이 폰의 보안 저장소(`expo-secure-store`)에만. 저장소·로그·설정 DB 에 없다 |
| 마스킹 | 밖으로 나가는 모든 길은 `redactForNetwork` 를 거친다 |
| 첫 실행 고지 | 통비법·의료법·병원 내규·마이크 표시·보관기한·앱 잠금을 하나씩 읽고 눌러야 시작된다 |

## 6. 남는 위험 — 숨기지 않는다

- **8시간을 통째로 녹음하는 설계 자체**가 "내가 없는 자리의 대화" 를 부른다.
  그건 통신비밀보호법 제16조 — 벌금형이 없고 징역 1년이 하한이다. 쓰는 사람
  책임이지만, 앱이 그 상황을 만들기 쉽게 되어 있다는 것은 사실이다.
  그래서 자동 기록은 기본으로 꺼져 있고, 첫 실행에서 그 말을 그대로 한다.
- **붙여넣은 글은 그 AI 회사의 서버에 남는다.** 마스킹을 거쳤어도 병동 대화다.
- **이것은 법률 자문이 아니다.** 실제로 배포할 거면 노무사·변호사에게 한 번 묻는다.
